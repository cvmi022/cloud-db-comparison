## 产品线：两家的数据库家族各有什么

基础形态高度对齐：两家都提供 MySQL 兼容的托管数据库和云原生版本，差异更多体现在生态整合和场景打磨上。

腾讯云最常用的是云数据库 MySQL（TencentDB for MySQL，早期叫 CDB），属于标准 MySQL 托管服务；再往上是 TDSQL-C MySQL 版，云原生架构，主打弹性扩缩和高并发场景。阿里云对应的是 RDS MySQL 和 PolarDB。

对开发者来说，这类产品都兼容 MySQL 协议，从自建 MySQL 迁过去基本不用改代码，选型重点因此落在别处：控制台是否顺手、和现有云资源的网络打通程度、计费方式是否灵活。

有个细节容易被忽略。腾讯云控制台在信息呈现上偏卡片式，CPU、内存、连接数这些核心指标一眼能看到；阿里云 RDS 控制台的参数和监控项更密，适合喜欢细调的人。这属于使用习惯问题，不影响功能。

## 计费模式：包年包月、按量计费还是 Serverless

业务长期稳定运行就选包年包月，短期项目或流量不确定就选按量计费，访问稀疏、经常空转则选 Serverless。

包年包月是提前买断资源，折算单价最低，代价是闲置也照付。按量计费反过来，随时开关、单价更高，适合临时测试或活动期间的临时扩容。

Serverless 是个人开发者问得最多的。规则是：没有请求时数据库自动休眠、不产生费用，有请求进来再按实际用量结算。对一个每天只有零星访问的个人博客或内部工具，这种模式确实能把成本压得很低。

但省钱有前提。按用量结算的单价通常高于包年包月的折算单价，这是所有按需计费产品的通例。如果服务全天都有稳定请求，Serverless 累计下来的账单可能超过同规格的包年包月，金额还不好预测。判断方法不复杂：看过去一个月的请求是不是集中在几个时段、有没有大段空转。有，就用 Serverless；没有，老老实实包年包月。

## 跨云迁移：换数据库到底有多麻烦

技术上可行，官方工具能覆盖，但前置条件和细节问题不少，通常需要一次完整的迁移演练。这也是为什么更省事的做法是一开始就把数据库放在应用所在的云上。

阿里云的数据传输服务 DTS 支持从腾讯云云数据库 MySQL（含 TDSQL-C MySQL 版）迁移到阿里云 RDS MySQL。流程本身是向导式的，麻烦的是前置条件：

- 腾讯云实例要开通公网访问，拿到外网地址和端口；
- 源库要有高权限账号（默认 root）；
- 走增量迁移的话，源库必须开启 binlog，且 `binlog_format` 为 `row`；
- 源库是 MySQL 5.6 及以上版本时，`binlog_row_image` 还必须是 `full`。

还有几个容易在预检查之后才被发现的问题：

- 结构迁移不支持 event；
- float 和 double 类型按固定精度读取（38 位和 308 位），业务对精度敏感的话要提前确认；
- 待迁移的表如果没有主键或唯一约束，目标库可能出现重复数据；
- 全量迁移会同时占用源库和目标库的读写资源，官方建议在业务低峰执行，比如两边 CPU 负载都在 30% 以下；
- 七天内的异常任务会自动恢复，可能把源库数据覆盖到目标库，迁移结束后要用 `revoke` 收回 DTS 账号的写权限。

把这些串起来看，换一家云从来不是点几下鼠标的事。它需要维护窗口、需要提前改好 binlog 参数，还需要演练一遍。

## 常见问题

**两家数据库能互相迁移吗？**

能查到的官方迁移文档主要覆盖阿里云 DTS 从腾讯云迁往阿里云这个方向。反方向迁移之前，先到腾讯云数据传输服务的文档里确认支持范围和参数要求，别直接照搬 binlog 配置。

**Serverless 是完全不花钱吗？**

不是。待机休眠时不计费，但只要有请求进来就按实际用量结算。访问量低才划算，持续有流量时不一定比包年包月便宜。

**数据库和应用不在同一家云上，会怎样？**

跨云访问要走公网或专线，延迟比同云内网高，还可能产生流量费用，安全组和白名单也要多配一层。能用同云内网就用同云内网。

**第一次买数据库，配置怎么选？**

从满足当前业务的最小规格起步，配合按量计费或 Serverless 观察一两个月的真实负载，再决定是否升级和转包年包月。数据库一般支持在线升配，起步买大属于浪费。
